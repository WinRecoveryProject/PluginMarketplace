# Zilvereyes Plugin Studio

Read `../../references/preservation-policy.md` before changing any plugin state.

1. Inventory the named roots and classify upstream reference, editable source, marketplace entry, installation, cache, archive and candidate separately.
2. Record the user's complete worklist. Do not reduce it to the currently active plugin.
3. Route new or updated plugin packages to `zilvereyes-create-plugin` or `zilvereyes-update-plugin`.
4. Route new or improved skills to `zilvereyes-create-skill` or `zilvereyes-improve-skill`.
5. Route skill discovery and installation to `zilvereyes-install-skill`; preview before mutation and refuse overwrite.
6. Route plugin/skill audits to `zilvereyes-evaluate-plugin`, and cross-package planning to `zilvereyes-plugin-portfolio`.
7. Create derived work under a new unique name. Never modify an upstream snapshot merely to avoid a duplicate display name.
8. Verify source state, package state and installed state independently.
9. Present proposed deletions or uninstalls as separate, exact decisions; do not infer permission from cleanup language.
