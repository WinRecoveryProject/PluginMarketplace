# WinRecoveryProjectLinter 0.1.2

Rettelserne behandler de observerede årsager til INCOMPLETE i Windows-scanningen.
De ændrer ikke projektets kildefiler, forbindelser eller globale konfiguration.

- **Python:** JSON-protokollen læses nu eksplicit som UTF-8. Windows-pipen brugte
  cp1252/surrogateescape og kunne derfor ødelægge gyldig UTF-8, inklusive byte 9D.
  En særskilt filgrænse håndterer også reelt ugyldige Unicode-snapshots uden at
  afbryde resten af batchen. Den konkrete fil og manglende dækning rapporteres.
- **PowerShell:** analysen fordeles på højst otte filer pr. batch med 256 KiB som
  batchingmål. En større understøttet fil analyseres hel i eget batch. Det samme
  30-sekunders procesloft bevares; en fejlet batch gør ikke vellykkede batches
  usynlige. JSON-dækningen viser `checkedFiles` og `partial`/`failed`.
- **TOC:** statiske stigrænser og alle tokens kontrolleres før deferral af
  `[Game]`/`[TextLocale]`. Ukendte tokens skjules ikke af et kendt token på samme
  linje. Der opfindes ingen `[Family]`-binding, og ingen sti uden for roden læses.
- **Klargøring:** eksplicit setup forbereder pinned værktøjer i en verificeret
  per-user runtime uden for den flygtige plugincache. Den kan genbruges efter
  pluginudskiftning. Doctor og scan downloader eller installerer stadig intet.
  Integritetskontrollen dækker låst dependencygraph, versioner, metadata og valgte
  entryfiler; den er ikke en attestering af hver transitive fil.

## Verifikation før installation

67 tests bestod uden fejl eller spring over. Den sidste præcisering af
manifestteksten og fejlvejledningen bestod desuden fem native-pakketests.
Den genererede ZIP indeholder 48 eksplicit tilladte filer, ingen node_modules,
.tools, credentials eller globale indstillinger. Marketplace-snapshottet bevarer
derudover de to uændrede Git-politikfiler.

Frisk udpakning, faktisk eksplicit pinned setup og Lua/HTML/CSS-scanning bestod.
Efter pluginmappen blev flyttet, virkede de samme kontroller med den eksisterende
runtime uden gentaget setup. Et særskilt uafhængigt offlineforsøg dækkede også
TypeScript og fire negative parsertilfælde. Det er afgrænset funktionsevidens,
ikke en påstand om at alle projekter er fejlfrie.
